# ОмутОтдых

**ОмутОтдых** — учебное full-stack веб-приложение для поиска и бронирования гостиниц, баз отдыха и санаториев в Омутнинске.

Пользователь выбирает тип отдыха, даты и количество гостей, получает подходящие варианты размещения, настраивает питание и дополнительные услуги, а затем оформляет бронирование. Для сотрудников и администратора предусмотрены отдельные функции, статистика и управление данными.

Проект объединяет серверную логику на PHP, реляционную базу MySQL, хранимые процедуры, пользовательские сессии и адаптивный интерфейс.

> Проект разработан как учебная информационная система и демонстрирует полный сценарий работы с бронированием — от поиска свободного номера до сохранения заказа.

## Сценарий бронирования

1. Пользователь выбирает тип отдыха, даты и число гостей.
2. Сервер вызывает хранимую процедуру `getAvailableRooms`.
3. Из базы возвращаются номера, подходящие по вместимости, типу места и периоду.
4. Пользователь выбирает объект размещения и номер.
5. К заказу добавляются питание и дополнительные услуги.
6. Стоимость рассчитывается с учётом количества дней и выбранных опций.
7. После подтверждения данные пользователя и бронирования сохраняются в БД.
8. Система формирует текстовое подтверждение и HTML-письмо.

Промежуточные параметры заказа хранятся в PHP-сессии и передаются между этапами оформления.

## Работа с базой данных

В репозитории находится дамп `lihacht3_local.sql`, содержащий структуру, демонстрационные данные и серверные объекты.

Основные таблицы:

- `базы_отдыха` — гостиницы, базы и санатории;
- `номера` — варианты размещения;
- `пользователи` — данные клиентов;
- `учетные_данные` — логины и роли;
- `сотрудники` — данные сотрудников;
- `бронирующие` — оформленные бронирования;
- `услуги` и `стоимость_услуг` — дополнительные услуги;
- `типы_питания` и `пропитание` — варианты питания;
- `активы_и_бронь` — связь бронирования с местом, питанием и услугами.

### Хранимые процедуры и функции

- `getAvailableRooms` — поиск доступных номеров;
- `GetBookingDetailsByEmail` — получение бронирований пользователя;
- `getRoomInfo` — получение информации о номерах;
- `getServicesCost` — определение стоимости услуги;
- `GetUserCredentials` — получение данных для авторизации;
- `getTotalBookings` — подсчёт бронирований;
- `getTotalIncome` — расчёт выручки;
- `GetUserDetailsByID` — получение данных пользователя.

### Представления

- `hotelInfo` — агрегированная информация об объектах размещения;
- `количество_бронировавших_в_отелях` — статистика по объектам;
- `популярные_услуги` — рейтинг выбранных услуг.

## Локальный запуск

### Требования

- PHP 8;
- MySQL 8 или совместимая версия MariaDB;
- Apache, Nginx или встроенный PHP-сервер;
- расширение `pdo_mysql`.

Для удобного запуска под Windows можно использовать XAMPP, Open Server Panel или аналогичную локальную среду.

### 1. Клонирование

```bash
git clone https://github.com/Gonerr/RestOmut.git
cd RestOmut
```

### 2. База данных

Создайте пустую базу и импортируйте дамп:

```bash
mysql -u root -p database_name < lihacht3_local.sql
```

Дамп содержит выражения `DEFINER`, связанные с исходным сервером. При импорте в другую среду их может потребоваться заменить на локального пользователя или удалить.

### 3. Подключение

Укажите локальные параметры MySQL в `require/config.php`:

```php
$host = 'localhost';
$user = 'your_user';
$password = 'your_password';
$db = 'your_database';
```

### 4. Запуск

```bash
php -S localhost:8000
```

После запуска откройте:

```text
http://localhost:8000
```

Для реальной отправки писем необходимо отдельно настроить почтовый транспорт PHP.

## Безопасность

Текущая версия является учебным прототипом и не должна публиковаться как рабочий сервис без доработки.

Перед дальнейшим использованием необходимо:

- заменить и отозвать опубликованные учётные данные MySQL;
- вынести параметры подключения из репозитория;
- хешировать пароли через `password_hash`;
- проверять пароли через `password_verify`;
- хранить роль и статус входа на сервере, а не доверять значениям cookies;
- добавить защиту от CSRF;
- ограничить CORS;
- проверять допустимые имена таблиц и столбцов в административных запросах;
- настроить безопасные cookie-флаги `HttpOnly`, `Secure` и `SameSite`.
